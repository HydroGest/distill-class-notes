## ADR-027 文本模型切换:Kimi-K2.5(最终)

背景:9 月下旬起笔记质量崩塌(化学截断在公式中间、高数直接落"未命名"兜底模板)。根因:**网关的 Kimi-K2.6 变成强制推理模式**——隐藏思考吃掉全部 max_tokens(高数真实笔记思考 21846 字 ≈ 1.2 万+ token),6000 上限下正文被挤成空/截断;extra_body 各种 thinking 开关参数网关全部无视(实测 7 种均无效)。
过程:
1. `llm_integrate` max_tokens 6000 → 20000 + 记录思考量/finish_reason;
2. 候选实测:DeepSeek-V4-Flash 最优(思考 86-435 字、633 token、9-40s),但 **Token Plan 下 max_tokens 上限 ≤4096(≥6000 全 403),装不下整篇笔记,出局**;GLM-5.3-Flash/MiniMax 思考 2000-4300 字;
3. 终选 **Kimi-K2.5:思考 0 字、completion 363 token(比 Qwen3.8-Flash 1628 少 4.5 倍)、10-59s、Kimi 系笔记质量(⚠️/待确认 齐全)**。
修复效果:三篇受损笔记已重生成——化学 09-20(6714 字)、高数 09-21(5859 字)、未分类 09-23 无穷小量(4991 字,思考 0 字),原劣稿均保留 .旧稿.bak。

## ADR-001 放弃平板手写

背景:Redmi Pad SE 不支持主动笔,电容笔精度差。
决定:课上纸笔手写;平板只做展示(电子书/PPT)。

## ADR-002 纯 Markdown 文件夹(裸文件)

背景:想要笔记不被工具锁死,且流水线要直接读写笔记。
决定:笔记 = 文件夹里的 .md 文件,App 只是工具。
理由:不锁死任何软件;流水线直接读写文件;换编辑器零成本。

## ADR-003 笔记应用选 Obsidian(定位为纯编辑器)

背景:用户觉得 Obsidian 不好用(双链没用上)。
决定:Obsidian,但关闭双链/图谱,只用"打开文件夹/编辑/全局搜索",免费安卓端。
备选:Typora(无安卓端)、Joplin/思源(库模型,与 ADR-002 冲突)。
理由:文件夹原生 + 免费安卓端 + 搜索强;用户嫌弃的功能全部不用。

## ADR-004 不用 Syncthing / FolderSync 等安卓后台同步

背景:MIUI/HyperOS 绞杀后台服务;Syncthing 安卓端口碑差。
决定:安卓端**零后台服务**;所有传输都是前台动作(上传网页 / 分享目标 / USB 兜底)。
理由:后台同步类 App 在国产 ROM 上必被杀、耗电、不可靠;前台动作瞬时完成,杀不掉。

## ADR-005 服务器 = WebDAV 文件中枢 + 自动流水线

背景:PC 和平板/手机不同时在线,需要一个永远在线的节点。
决定:WebDAV 容器做文件传输,服务器 24h 在线干重活(转写/识别/整合/归档)。
理由:服务器是唯一可靠节点;WebDAV 是现成协议,安卓/PC 生态都支持。

## ADR-006 STT 用本地 FunASR(或 faster-whisper)

备选:云 STT(讯飞/阿里,~1-2 元/小时,一学期 30-60 元)。
决定:本地免费,中文效果好,支持热词/时间戳;按内存实测在 FunASR 与 faster-whisper 间选。
理由:成本 0 vs 几十元,质量够用,隐私更好。

## ADR-007 照片用 VL API 而非 PaddleOCR

背景:OCR 只给文字,不理解内容;用户问"图片走多模态 LLM?考虑成本"。
决定:照片 → 多模态 LLM(通义 qwen-vl-plus 或智谱 GLM-4V-Flash)。
理由:VL 成本近零(几厘/张,一学期 2-5 元,GLM-4V-Flash 甚至有免费档),且直接产出结构化要点/表格/mermaid 草稿,价值差一个量级。

## ADR-008 采集设备 = 手机,平板仅展示

背景(更正):用户课上录音/拍照都用手机;平板放支架上展示电子书/PPT,不想动。
决定:手机是唯一移动端采集与上传入口;平板完全退出流水线,零配置。
理由:尊重使用习惯;系统反而更简单(少一个设备的 App/配置)。

## ADR-009 传输 = 前台手动选择,不做全量自动上传

背景:相机文件夹混着生活照,不知道哪些是笔记。
决定:主路径 = 图库选中 → 分享 → 上传(选择性在传输时由人完成);可选未来做"源头分文件夹"或"VL 自动筛选"(M3)。
理由:选择性是人的事;全量自动上传会把生活照卷进流水线(隐私 + 噪音)。

## ADR-010 不用 n8n / Node-RED 自动化平台

背景:曾考虑用工作流引擎搭流水线。
决定:流水线 = 单个 Python 脚本(pipeline.py)+ cron。
理由:固定三步批处理,脚本更简单、可逐行读懂;FunASR 是 Python 库,n8n(Node)硬接要起微服务,一套变两套;服务器只剩 3.4G 内存,少装一个是一个。

## ADR-011 不用 Nextcloud

背景:服务器内存只剩 ~3.4G。
决定:不用 Nextcloud 这类重型自托管;用轻量 WebDAV 容器代替。
理由:Nextcloud 吃资源、维护成本高,而需求只是"文件收发 + 目录访问"。

## ADR-012 分组 = 时间聚簇 + 三层课程信号 + 锚点照片

背景:服务器怎么知道文件属于哪一课、哪些文件合成一篇笔记。
决定:同一时间窗(间隔 >60-90 分钟切分)= 同一会话;课程由"上传标签 → VL 识别 → 校对确认"三层决定;手写纸笔记照片作为会话锚点。
理由:自动化"猜" 90%,人校对补 10%;每一层都有 2 秒内的修正入口,不做绝对正确的幻想。

## ADR-013 WebDAV 用 wsgidav(纯 Python),不用 Docker 容器

背景:计划用 bytemark/webdav 容器,但服务器 Docker 配置的镜像源(腾讯 mirror.ccs.tencentyun.com)已失效,拉取失败;重启 Docker 会中断正在运行的 napcat(QQ bot)与 natfrp。
决定:WebDAV 用 Python 的 wsgidav + cheroot,随蒸馏自己的 venv 跑,端口 8082。
理由:同样标准 WebDAV 协议,零容器依赖,不动 Docker 不影响现有服务;重启后由 start.sh 拉起。

## ADR-014 STT 加速:核显(780M)路线暂缓,列为 M2

背景:用户问核显能否加速 STT。服务器为 AMD Phoenix APU(Radeon 780M),RADV Vulkan 已就绪,/dev/dri 正常。
决定:当前保持 faster-whisper small + CPU + 夜里 cron 批处理;核显加速(whisper.cpp + Vulkan,预计 2-3 倍)列为 M2 可选优化。
理由:已选"夜里跑",速度不敏感;whisper.cpp 编译 + 模型转换是中等工程,收益不迫切;ROCm 在核显上过于折腾,不做。

## ADR-015 课程分类改为控制台可管理(data/courses.json)

背景:用户反馈"课程没法添加分类"——之前课程列表写死在 config.yaml,只能手改。
决定:课程列表存 data/courses.json(缺失时从 config.yaml 种子生成),控制台「+管理」对话框可增删;待分类/废纸篓/未分类为系统分类不可删;有文件或笔记的课程禁止删除。

## ADR-026 热词自动补充(零 LLM):从笔记库按课程提取

背景:STT 热词此前靠手工维护 `[两个结合, 中国式现代化]`;需求是热词由已生成笔记自动补充,且**提取过程零 LLM 调用**。笔记整合流程维持原样(LLM 正常使用)。
方案:流水线每次启动时,用 jieba 对每门课的全部笔记分词,过滤中英文停用词 + LaTeX 记号 + 频次 <2 的词,取每课最高频 40 个术语写 `data/hotwords/{课程}.txt`;`default.txt` = 配置热词 ∪ 全库高频词。转写时按会话课程加载对应热词文件(funasr 实测生效),未知课程用 default。
实测:高数课热词 = 极限/数列/子列/收敛/例题/放缩…,生物 = 进化/基因/RNA/DNA…,funasr 日志确认加载 `data/hotwords/高数.txt`。
阈值可在 config 调:`hotword_top`(40)、`hotword_min_freq`(2)。

## ADR-025 STT 英文支持:按课程路由 + 语言自动检测

背景:用户有英语课(全英文/中英混合),当前 paraformer-zh 实测纯英文崩坏("The Hox gene family…" → "The oxyian family cont"),但中文夹带术语可用。
方案:
1. `stt.english_courses: [英语课]`:这些课录音强制 faster-whisper-small(英文实测近乎完美),语言参数 `language="zh"` 改为 `None` 自动检测;
2. `stt.auto_lang: true`:未知课程(待分类/未分类)录音先用 whisper 首窗(~30s)快速检测语言,en → whisper,zh → funasr(保留热词与最高中文质量);
3. 模型缓存按引擎分 key(`fw:small` / `fa:paraformer-zh`),同一进程双模型共存互不干扰;
4. transcribe 增加 course 参数,主循环与 merge_into 均传入课程。
实测:英语课指定路由 en p=0.95 ✓;待分类英文自动切 ✓;真实中文录音检测 zh → funasr 输出清晰 ✓。
代价:whisper-small 加载 ~4.6min/次、处理比 funasr 慢 ~7 倍(夜里跑可接受),中文课完全不受影响。

## ADR-024 笔记页深度重构:设计系统 + CodeMirror 编辑器 + 滚动修复

背景:用户反馈「丑 + 滚轮滚不动」,要求顶级打磨,允许使用顶尖轮子。
设计系统(theme.js):冷静靛蓝主色、柔纸底、发丝边框、圆角统一、明暗双主题;AppBar 改为纸面质感+底部发丝线,桌面 Tabs 靛蓝指示条。
笔记库:统计药丸、圆角搜索框(聚焦光环)、吸顶课程头、卡片 hover 浮起、元信息药丸(录音/照片)、全文搜索高亮、卡片快捷 ✏️ 编辑。
编辑器:换 CodeMirror 6(@uiw/react-codemirror)+ markdown 语法高亮 + 明暗主题 + 8 键格式工具栏(加粗/斜体/标题/列表/公式/表格/引用/代码)+ 分屏实时预览。
修复的 BUG:
1. **滚动陷阱**:`overflowX:auto` 会隐式把 overflowY 变 auto → 横向滚动容器吞垂直滚轮事件;补 `overflowY:'hidden'`+固定高度;
2. **严重回归**:NoteDialog 里 EditDialog 无条件挂载且 `open` 写死 → 打开任意笔记全屏编辑器直接盖住,且 title 在 data 加载前被 useState 捕获为空 → 保存永远「标题不能为空」;改为 `{editOpen && data && <EditDialog/>}` 条件挂载;
3. **api_note 缺 title 字段** → NoteDialog 标题一直回退成目录名、重命名框为空;补 title(取 H1)。
验证:Playwright(系统 Chrome)全元素滚轮测试、详情/编辑器/保存落盘 E2E、移动端(390×844)与暗色模式全部通过。

## ADR-021 合并加固:无锚点会话不参与合并 + 未知课程严格区间

背景:09-15 16:05 运行中,生命演化课 7 个文件(录音 14:23 + 照片 14:30-14:58)被误并入高数演示草稿(会话时间 = md 修改时间 13:32,距 14:23 有 51 分钟,超出 30 分钟容差却仍被并入),导致一篇笔记被两节课内容污染。
根因:① 纯文本草稿没有附件,会话时间退化为 md 文件 mtime(与课程时间无关);② 上传选「待分类」时课程过滤被禁用,30 分钟容差跨课程误并;③ 「同课程同一天=一节课」兜底过宽(错开 51 分钟也并)。
修复:
1. 无附件会话(时间锚点缺失)→ 标记 t0/t1=None,永不参与时间合并(手动合并不受影响);
2. 上传未选课程(待分类/未分类)→ 只接受严格落在会话区间内的文件,不开 ±30 分钟容差;
3. 「同课程同一天」兜底仅对 **≥17 点**的晚间补拍手写笔记生效,白天错开的不算;
4. 数据修复:7 个文件归还生命演化课,高数草稿截断,生命演化用全量素材(录音+21 照片)重新整合。

## ADR-020 笔记生成:内容决定结构的完整复习笔记,禁总结腔

背景:旧模板「核心要点 3-8 条 + 易错点 + 待补」把模型逼成摘要器,产出的是概括不是笔记。
决定:
1. 提示词反转:输出「能直接复习的课堂笔记」——记录知识本身,结构由素材决定(录音课按讲课顺序、照片课按知识点/例题),定义/公式/定理写全,例题完整展开(题目→思路→步骤→结论),老师强调点以「⚠️」内嵌;
2. 严禁总结腔:「本课介绍了/核心要点/综上所述/总而言之」等一律禁止;不编造,缺失处标(待确认);
3. VL 同步改:照片从「每条≤40字要点」改为完整抄录(标题、公式、例题全过程,LaTeX),max_tokens 1000→2000;
4. 演示验证:高数数列极限新版(未分类/2026-09-14_03)含 ε-N 定义、两道证明方法、有界性/唯一性完整证明,零总结腔。

## ADR-018 一节课 = 同一课程 + 同一天;跨课程永不合并

背景:用户分次上传同一节课的录音/照片,旧逻辑按"时间间隔 60 分钟"切分,课间(81 分钟)被误拆成两节课;合并逻辑还曾把高数照片误并入其他课程笔记。
决定:
1. 分组:同一课程目录 + 同一天 = 一节课(课间休息不算新课);跨天、跨课程各自成篇;
2. 合并:只匹配同课程已有会话(课程取自目录名或笔记 frontmatter),无同课会话则全部留作新会话,绝不跨课程合并;时间容差收紧到 30 分钟;同课程同一天的晚间补拍手写笔记照片也算同一节课;
3. 课程来源:上传页选的课程目录直接写入草稿 frontmatter(校对页预选),LLM/VL 不再猜课程;
4. 兜底:校对页新增"合并到其他草稿"手动合并(附件并入 + 内容追加 + 回待校对)。
5. 控制台支持 LaTeX 渲染(KaTeX:$...$ / $$...$$),理科笔记公式可读。

## ADR-017 一节课 = 一篇笔记:补充素材自动合并

背景:用户录音、照片、手写笔记往往分批发来(录音先到、照片后到)。若各自成篇,同一节课会有多篇笔记;归档时还会撞目录名。
决定:
1. 流水线运行时,新文件按"拍摄/录音时间"匹配已有会话(区间最近者,允许 gap 容差),并入其附件目录并追加"补充材料"段落(新照片 VL、新录音转写);
2. 归档(校对页一键)时目标目录已存在 → 自动合并:附件并入 + 源笔记内容追加为"合并笔记"段落,不再报错;
3. 已定稿会话被并入新内容后,状态回"🟡 草稿"并移回未分类,等待重新校对。
理由:保证"一节课一篇",同时任何合并都经过人工校对确认,不静默改动已定稿内容。

## ADR-016 STT 升级:funasr(paraformer-zh)为主力引擎
