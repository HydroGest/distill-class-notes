# 蒸馏 (Distill) — 完整设计方案

> 本文档记录系统设计与实现的全貌:名字由来、背景、目标与原则、工作流、数据模型、组件、成本账、约束与风险、里程碑。
> 每个技术取舍的详细理由见 [决策记录.md](./决策记录.md);README 见 [../README.md](../README.md)。

## 0. 名字

**蒸馏 (Distill)**:课堂的录音、照片、手写关键词是"粗原料",每晚流水线像蒸馏一样提取精华,产出结构化笔记草稿;人工校对 10 分钟,把 80 分草稿提纯到 95 分定稿。

## 1. 背景与动机

- **使用者**:理工科大一学生,课程以高数 / 线代 / 编程为主,另有思政类课程。
- **现状**:课上纸笔记录关键词提纲 + 手机录音 + 手机拍照;课后想整理成体系、可检索、多端可看。手动整理太耗时,笔记常常躺在录音里吃灰。
- **痛点**:
  - Obsidian 之前"不好用"——双链用不上,打开即乱的笔记库没有价值;
  - 安卓后台同步类 App 在 MIUI/HyperOS 下体验差(被杀后台 / 耗电 / 不可靠),靠后台同步传文件行不通。
- **设备分工**:

| 设备 | 角色 | 说明 |
|---|---|---|
| 手机 | 课上录音 + 拍照,课后上传 | **唯一移动端采集与上传入口** |
| 平板 | 支架上展示电子书/PPT | 不进流水线,零配置(无主动笔支持,电容笔精度差 → 放弃平板手写) |
| PC | 课后整理、校对、阅读 | 连接服务器 |
| 宿舍无头服务器 | 文件中枢 + 全部自动处理 | 24h 在线;示例配置 Ubuntu 24.04 x86_64,16 核 / 内存 14G(可用约 3.4G)/ 磁盘 393G 可用 |

## 2. 目标与原则

**目标:课上 5 分钟记录 + 课后 10 分钟校对 = 一篇结构化、可检索、可复习的笔记。**

原则:

1. **课上手写纸笔,课后电子整理** —— 手写是记忆编码,电子是检索复用,各干各的。
2. **文件夹即笔记** —— 纯 Markdown 文件,不锁任何 App,随时可换编辑器零成本。
3. **自动化给 80 分,人工补 20 分** —— 流水线产出草稿,人只做 10 分钟校对;100% 自动化的笔记系统不存在。
4. **安卓端零后台服务** —— 所有传输都是前台动作;后台同步类 App 在国产 ROM 上必被杀。
5. **重活全在服务器** —— 服务器 24h 在线,负责处理、归档、备份;手机/PC 只做轻量动作。

## 3. 工作流总览

```
课上(你):纸笔记关键词 + 手机录音 + 手机拍照(板书/PPT)+ 下课时给纸笔记拍一张(锚点)
  ↓
课后(你,前台动作):手机图库 → 分享 → 上传控制台(顺手选课程)→ 服务器 data/inbox/<课程>/
  ↓
夜里(自动,cron 23:00):pipeline.py
  ├─ 分组:同一课程 + 同一天 = 一节课(课间休息不算新课,跨课程永不混组)
  ├─ 已有会话匹配:拍摄/录音时间落在已有会话区间内 → 补充素材自动并入
  ├─ 录音 → STT(funasr 主力 / faster-whisper 英文)→ txt + srt(带时间戳)
  ├─ 照片 → VL API → 完整抄录 + 结构化要点(LaTeX 公式/表格/mermaid 草稿)
  ├─ 文本 LLM 按素材整合 → 草稿笔记(data/笔记/未分类/<日期>_<n>/)
  └─ 热词库更新:jieba 从已归档笔记按课程提取高频术语(零 LLM)
  ↓
早上(你,10 分钟):控制台校对——确认课程、合并/拆分分组、补答题规范 → 一键归档到 data/笔记/<课程>/
  ↓
随时(你):Obsidian 打开 data/笔记/ 或网页控制台,阅读、搜索、复习
```

## 4. 数据模型与目录结构

### 会话(Session)

**一节课 = 一个"会话" = 一篇笔记。** 会话 = {录音若干段, 照片若干张, 锚点照片 1 张(手写纸笔记)}。

### 分组依据(服务器怎么知道"哪些文件是一篇笔记")

1. **课程目录 + 日期**(主):上传时选的课程目录决定了会话的课程;同一课程目录 + 同一天 = 一节课,课间休息不算新课;跨天、跨课程各自成篇,永不混组。
2. **补充素材并入**:新上传的录音/照片按"拍摄/录音时间"匹配已有会话(同课程、时间落在会话区间内,容差 ±30 分钟),并入附件目录并追加"补充材料"段落——保证"一节课一篇"。
3. **课程识别(三层信号)**:
   - ① 上传时打标签(最准,2 秒):上传页有课程按钮,默认选中上次用的课;
   - ② VL 内容识别(兜底):PPT 标题页/板书关键词能猜出课程,猜的标注"待确认";
   - ③ 校对确认(最终):草稿头部课程字段,校对时改。
4. **锚点照片**:下课时给手写纸笔记拍一张——VL 识别关键词作为草稿骨架,天然标记"这节课讲了什么",也是最强分组信号;同课程同一天晚间(≥17 点)补拍的手写笔记也算同一节课。

### 目录结构

```
~/distill/
├── README.md
├── config.example.yaml  配置模板(复制为 config.yaml)
├── requirements.txt     Python 依赖
├── pipeline.py          每晚批处理流水线
├── upload.py            上传 + 控制台 API 服务
├── webdav.py            WebDAV 文件中枢
├── start.sh / stop.sh   启停脚本
├── docs/
│   ├── 方案.md          本文档
│   ├── 决策记录.md       每个"为什么不用 X"的理由
│   └── Obsidian配置清单.md
└── data/                个人笔记数据(不进入公开仓库)
    ├── inbox/           文件传输中枢(WebDAV 挂载点)
    │   ├── <课程名>/    上传落点(按课程分目录)
    │   └── 废纸篓/      被判定为非笔记的内容(可选,M3)
    ├── 笔记/
    │   ├── 未分类/      流水线草稿初落点(<日期>_<n>/ 子目录)
    │   ├── 思政课/
    │   │   ├── 2026-09-14-理论创新与理论创造/   (示例:每篇笔记一个目录)
    │   │   │   ├── 2026-09-14-理论创新与理论创造.md
    │   │   │   └── 附件/ 录音 + 照片(板书、PPT、手写关键词)
    │   ├── 高数/        (以后)
    │   └── ...           (以后)
    ├── hotwords/        每课热词文件(流水线自动生成)
    ├── status.json      运行状态(供控制台读取)
    └── pipeline.lock    进程锁(防止手动与 cron 重叠)
```

## 6. 笔记模板

每篇笔记 = YAML 头部(课程/日期/来源/状态)+ 正文(按课程类型):

```markdown
---
课程: 思政课            # ⚠️ 待确认
日期: 2026-09-14
来源: 附件/ 目录(录音、照片)
状态: 🟡 草稿
---

# 标题
## ...(正文由 LLM 按素材结构组织)
```

- **思政类**:主线 → 核心要点 → ⚠️ 易错点(答题规范)→ 待补
- **理工类**:定义 → 定理/性质 → 例题 → 易错点 → 待补
- 状态:🟡 草稿(流水线产出)→ 🟢 定稿(校对完成)
- 正文生成要求(ADR-020):内容决定结构,记录知识本身;例题完整展开(题目→思路→步骤→结论);老师强调点用「⚠️」内嵌;严禁"总结腔";素材缺失一律标"(待确认)"、不编造。

| 文本 LLM | 几厘/千 token | ~1-2 元 |
| STT | 本地 FunASR | 0 元 |
| 服务器资源 | 已有 | 0 元 |
| **合计** | | **<10 元/学期** |

> 说明:照片在流水线中会先压缩(按分辨率计费),实测单张照片压缩后约 110 图片 token;文本模型单篇整合约数百 token(按网关实测选型,见 ADR-027)。STT 全程本地运行,不产生 API 费用。

## 8. 约束与风险

1. **PWA 分享目标需 HTTPS**:基础上传页局域网 IP 直连即可用;分享目标需证书(可选 Tailscale 自动签发)。
2. **内存受限**:部署机可用内存约 3.4G,STT 按实测选轻量方案(funasr / faster-whisper),避免任何重型服务(这也是不用 Nextcloud/n8n 的原因)。
3. **手写公式不可自动结构化**:高数/线代的公式整理靠人(或拍照贴原图)。
4. **录音质量影响 STT**:教室噪声/多人说话,转写稿会乱;定位是"检索索引 + 草稿",不是最终笔记。
5. **隐私**:照片会经过云端 VL API;生活照不要进管线;介意则不做全自动筛选(M3),或等有 GPU 跑本地 VL。
6. **校对不可省**:答题规范("一带一路重大倡议"这类)老师强调的东西,模型不知道,只有你知道。
